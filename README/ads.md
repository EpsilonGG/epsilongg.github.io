# 右侧广告位：预留但不外显

[← 返回仓库首页](../README.md) ｜ [项目说明](project.md) ｜ [Fork 指南](fork.md)

文章页右边那条 208px 的空栏，是可以放广告的。

**但默认是关的，页面上什么都不显示，也不加载任何第三方资源。** 理由很实际：这个站没有外部流量，也没有需要导流的内容产品，广告位开着只会拖慢首屏、破坏气质，还多一份隐私负担。所以代码只把「位置」留好，开关关着。

想开的时候按下面做，**版面不用动**。

---

## 0. 为什么开广告不会把正文挤歪

文章页是六列网格：

```
[左栏轨道 14rem] [间隔 2rem] [正文 38rem] [留白 1rem] [右栏 13rem] [间隔 2rem]
                                                          ↑
                                                     广告位住这里
```

右栏这一列本来就是空的——它的唯一作用是**让整组轨道左右配平，正文落在视口正中**。广告位就住在这一列里，所以：

- 不开广告：这一列空着（现在就是这样）
- 开广告：这一列放横幅，正文位置一个像素都不动

左栏轨道为什么是 14rem 而不是 13rem：多出来的 1rem 不是给左侧栏用的（侧栏本身仍是 13rem，靠右贴齐，那份留白落在它外侧），而是用来抵消右侧那道 1rem 的 `--rail-gutter`。两侧总宽都是 16rem，正文才继续居中，同时正文和广告之间有 16px 呼吸区——不加这道留白，广告图会紧贴正文最后一个字。

改这两个 token 时记住等式：**`--sidebar-w` = `--rail-w` + `--rail-gutter`**。别把广告挪到别的列或者用 `position: fixed` 挂到边上，那样正文会被顶偏。

## 1. 放得下什么尺寸

右栏宽 208px（`--rail-w` = 13rem），所以：

| 尺寸 | 放得下 | 说明 |
| --- | --- | --- |
| 200×200 | ✅ | 方形，最稳，左右各余 4px |
| 160×600 | ✅ | 竖幅（skyscraper），一屏一个 |
| 120×600 | ✅ | 同上，更窄 |
| 300×250 | ❌ | 超宽，会溢出或被迫缩小 |
| 728×90 | ❌ | 横向长条，放不进竖栏 |

要放 300×250 这类尺寸，得把 `--rail-w` 调大（`src/styles/tokens.css`），同时按上面的等式把 `--sidebar-w` 一起配平——左侧栏因此也会变宽，两侧才保持对称。这是有意的：对称是这套版面的前提。

## 2. 怎么开

### 2.1 图片横幅（推荐，DLsite 那类联盟计划就是这种）

1. 把横幅图片放进 `public/images/ads/`，例如 `public/images/ads/xxx-200x200.png`
2. 改 `src/config/ads.json`：

```json
{
  "enabled": true,
  "label": "广告",
  "slots": [
    {
      "image": "/images/ads/xxx-200x200.png",
      "href": "https://www.dlsite.com/...?affiliate_id=你的ID",
      "width": 200,
      "height": 200,
      "alt": "广告：某某作品"
    }
  ]
}
```

`width` / `height` **必须写横幅的真实像素**。这不是装饰：浏览器靠它在图片下载完成前就占好位置，否则广告一加载页面就往下跳一截（CLS）。

### 2.2 脚本类广告

A8、もしも 这类平台给的不是图片，是一段 `<script>`。不要往 JSON 里塞——引号转义很难看，而且容易漏。直接打开 `src/components/ArticleRail.astro`，在文件末尾标注的位置粘进去，并**给外面那层写死高度**：

```astro
<div class="article-rail__slot" style="height: 600px">
  <!-- 广告平台给的代码 -->
</div>
```

不写高度，脚本加载前后页面会跳。

## 3. 联盟分成计划是怎么回事（以 DLsite 为例）

DLsite 的 アフィリエイト（affiliate）是**成果报酬型（CPS）**：你在后台申请、拿到一个 affiliate ID，然后用两种东西去投放——

1. **带 ID 的链接**：形如 `https://www.dlsite.com/...?affiliate_id=xxxx`，用户点了之后在有效期内下单，成交额按后台公布的比例分成；
2. **横幅（バナー）**：后台直接给固定像素的图片，图片本身已经带好跟踪参数，点上去就是上面的链接。

比例、有效天数、结算门槛都会变，以后台公布的为准，别写死在文档里。

对本站的意义只有一条：**它是「固定像素的图片 + 一个链接」**，正好对应 `ads.json` 的 `image` + `href`。所以这一类广告不用写任何新代码，填配置就行。

## 4. 合规与体面

- **必须标「广告」**。`label` 会渲染在广告位上方（现在写的是「广告」）。日本《景品表示法》要求广告可识别，国内《互联网广告管理办法》同样要求显著标明「广告」。别去掉这个标签。
- 链接已经带了 `rel="sponsored noopener noreferrer"` 和 `target="_blank"`：`sponsored` 是告诉搜索引擎这是付费链接，`noopener` 是防止新标签页拿到 `window.opener`。
- 图片带 `referrerpolicy="no-referrer"`，不把来源页地址漏给广告服务器。
- **广告内容要和站点内容有关系**。一个黑白灰、没强调色的个人站，挂一张大红大绿的横幅，气质立刻垮。真要做，优先选同人志、画集、音乐这类和站内文章同源的。

---

## 5. 副作用，先说清楚

| 项目 | 代价 |
| --- | --- |
| 图片横幅 | 多 1–2 个请求，200×200 + 160×600 约 30–80 KB（看图片格式） |
| 脚本广告 | 第三方 JS：几十到几百 KB，可能带 cookie、可能被拦截器挡住、可能拖慢 LCP。**这是唯一会真正伤性能的选项** |
| 与背景图模式同时开 | 栏会压在纸面边缘（纸面 46rem，栏在它右边一点）。有毛玻璃兜底，能看清，但不算好看——建议二选一 |
| 移动端 | 不显示（≤1023px 没有这一列），所以只有桌面访客会看到 |

---

## 6. 关掉

`src/config/ads.json` 里把 `enabled` 改回 `false`，或者清空 `slots`。产物里连 `<aside>` 标签都不会出现——不是 `display: none`，是根本不渲染。
