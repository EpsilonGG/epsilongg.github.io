转发条目怎么落地：两个方案，同一份数据

样本是已发布的第一期 26102522（2026-10-25，127 人）。名单外的 66 个 handle 全部是 名单内成员的转发，转发者 100% 可读（metadata.retweeted_by），没有一条是「无法读取转发者」。 所以这次要比的不是「读不读得到」，而是这批内容放在哪一栏、以谁的名义说。

下面两块的排版不是示意图：内联的是线上构建出来的 CSS，样张用的是日报页真实类名， 字号、行高、两端对齐、姓名链接的颜色都和 /daily/26102522/ 一致。

方案 A · 只归名

把转发内容并到转发者名下，句首写「转发提到了」。信息最全，但重度转发者那一行会变成清单。

方案 B · 只开主题栏

转发条目一律不进「详细」，集中到新开的一栏，按「聊人 / 聊音声 / 聊事情」三段概括， 原发账号的名字隐去（写成「有听众」「一位画师」「有社团」）。

看完这两块之后的判断

数据是偏向 B 的。详细栏原有 2149 字，其中 997 字（46%）来自转发、不是本人说的话； 把它们挂回转发者名下，等于让 30 个人的一句话里混进半句别人的内容。方案 A 在「大山チロル」这类 重度转发者身上会直接失效——当天没有原创发言，整行变成 8 条互不相干的 VRChat 杂项。

但 A 保住了 B 丢掉的那层信息：谁转了谁的什么。如果以后要做「扩散度」「谁在帮谁推」， 这层关系是原料，B 之后就查不回来了——除非它同时留在数据里（不进页面，但进 report.json）。

所以推荐 B，前提是 A 的那层关系不丢在数据层：转发条目在 report.json 里保留 retweeted_by 与 original_author，页面上只呈现三段概括。这样哪天想改回 A， 不用重新抓数据。
