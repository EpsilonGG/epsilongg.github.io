2.2 OG 图接动态生成：要做什么

目标：构建期为每个页面生成一张 1200×630 的 PNG，内容是该页的标题、描述、日期与栏目，写进 og:image 与 twitter:image。

做法是一条 Astro 端点，不是脚本：

// src/pages/og/[...slug].png.ts
export async function getStaticPaths() { /* 笔记 + 日报，两条来源合成一份列表 */ }
export async function GET({ props }) {
  const svg = renderCard(props);                 // 纯字符串拼 SVG
  const png = new Resvg(svg, {
    fitTo: { mode: 'width', value: 1200 },
    font: {
      fontFiles: ['./assets/fonts/NotoSansSC-subset.woff2'],
      loadSystemFonts: false,                    // ← 关键，见下
      defaultFontFamily: 'Noto Sans SC',
    },
  }).render().asPng();
  return new Response(png, { headers: { 'content-type': 'image/png' } });
}

五个动作，按依赖顺序：

  1. 模板：一个函数，输入 { kicker, title, description, date, site }，输出 SVG 字符串。版面就是本站的语言：白底、黑字、一条细线、右下角站点名。不需要图片、不需要渐变。
  2. 固定字体：把思源黑体/Noto Sans SC 子集化后放进 assets/fonts/，构建时通过 fontFiles 传入，并关掉系统字体（loadSystemFonts: false）。
  3. 断行与截断：resvg 不会自动换行，<text> 一行就是一行。要自己按「字号 × 字数」估算宽度折行，标题最多 2 行、超出截断加省略号；描述最多 2 行。
  4. 接入 meta：把生成的路径作为 image 传给 BaseLayout。现有的 og:image / twitter:card 逻辑不用改，只要传对值就会自动切成 summary_large_image。
  5. 缓存：按「标题 + 描述 + 日期」算 hash 作文件名，未变则复用。现在 16 张图全量生成约 1 秒，暂时不需要缓存；超过 100 页再加。

四个会踩的坑

坑现象解法
系统字体本机渲染正常，CI 上全是方框（ubuntu-latest 没有中文字体）；或者本机与 CI 挑到不同字重，断行位置差一个字loadSystemFonts: false + 仓库内字体文件。这是「固定字体」四个字的全部意义
字体体积Noto Sans SC 全量约 10 MB，为了 16 张图把仓库撑大十倍子集化到「常用 3500 字 + ASCII + 中文标点」，约 1.2–1.8 MB；再狠一点按构建产物里实际出现的字符动态子集
不换行长标题直接溢出画布，右边被裁掉自己折行；中文按等宽估算即可（全角 1em、半角 0.5em），英文单词不能从中间断
字体族名SVG 里写 font-family: "Noto Sans SC"，渲染出来却是默认字体名字必须是字体文件内部的 family name，不是文件名。子集化后名字常被改掉，用 fontkit 读一遍确认

与日报 M5 共用什么：同一个 renderCard()、同一份字体、同一套断行函数。差别只在数据源——笔记读 frontmatter（标题 / 描述 / pubDate），日报读 report.json（期号推导的标题 / 今日看点第一条 / published_at）。所以 M5 的四个工作包（模板、字体子集、断行、接入）做完，主页的 OG 也就同时做完了；反过来也一样。这也是把它算成「一件事」而不是两件的原因。

2.3 这件事的意义

  1. 分享卡片是本站唯一的站外门面。这个站是「长文归档」，读者多半从 X、QQ、Discord 的链接点进来，不是从首页逛进来。链接被贴出去时，卡片就是第一屏；现在 16 个页面共用一张默认图，等于放弃了这一屏。
  2. 日报尤其吃亏。日报的标题是「2026 年 10 月 25 日 22:00」——卡片上只有日期，信息量为零。动态图能把「今日看点」的第一条压上去，这才是能让人点进来的东西。
  3. 构建期生成，访客零成本。resvg 是 Rust 写的 SVG 渲染器，构建时把 SVG 渲染成 PNG，产物是静态文件。对比两条常见路线：Satori 要拖进 React/JSX 与 WASM，Playwright 要拖进一个 Chromium；resvg 两者都不要，构建时间增加约 1 秒。这符合「不引入运行时依赖」的铁律。
  4. 顺带满足平台格式要求。微信、X、Discord 对 og:image 只认 PNG/JPEG，不认 SVG。用 resvg 直接出 PNG，省掉「先生成 SVG 再想办法转换」这一层。

不做的部分：不做每篇文章的「封面大图」（那是另一件事，需要文章自带配图），不做动态文字排版（渐变、阴影、彩色标签）。这个站的视觉是黑白灰、无阴影、圆角 6px，卡片照抄这套即可；一旦开始给卡片上色，它就和站点不是一套东西了。

2.5 为什么比这些维度

第一版的矩阵列了「外部 JS / 搜索 / i18n / 动态 OG / 评论 / 日报栏目」。这六个维度不是随手挑的，它们各自对应本站的一条约束——换一个说法：每一列都在问「如果换成它，我会失去什么」。

维度为什么比它对本项目意味着什么
外部 JS / 水合十个里八个是「主题/模板」，而模板的默认形态决定了访客要下载什么：Astro 系接近零 JS，Next.js 系则带一整套运行时本站零外部 JS、脚本全部内联（10.1 KB）。换成 Next.js 系，首屏立刻多几百 KB
搜索读者第一次来会搜；搜不到就会走。这是「内容多了以后」第一个暴露的能力缺口现在只有标题级。§3.5 用实测数据回答「要不要上全文」
i18n模板都带 i18n，因为它们的用户是「不知道自己要写什么语言」的人本站只有中文。带 i18n 的模板会引入一层「文案键值表」，改一句话要动两个文件
动态 OGastro-paper / AstroWind / leerob.io 都有，说明这是「现代个人站」的事实标准本站没有。§2.2 把它变成可开工的规格
评论minimal-mistakes 带 Disqus，Quartz 带 Giscus——都意味着把读者数据交给第三方本站不做。不是不会，是决定不做：无后端、无第三方脚本是铁律
日报类栏目十个里一个都没有。这是本站唯一「别人没有」的东西，也是唯一没法对标的东西§4.4 单独处理：日报没有对标物，只能自己和自己比

还有两条没有放进矩阵，因为放进去会失真：

  • Star 数本身不是维度。模板的 star 来自「clone 的人多」，个人站的 star 来自「作者有名」。两者不可比，所以本站那格留空。
  • 代码行数不是维度。Quartz 有 4 万行，本站 src 约 6 千行；但 Quartz 要支撑几百种配置组合，本站只服务一个人。行数差异是定位差异，不是质量差异。

3.3 标签收敛为六个

之前 8 篇文章用了 11 个标签：访谈、翻译、声优、笔记、游戏、卡牌游戏、冒险游戏、剧作、画集、视觉小说、示例。每个标签平均不到一篇——这不是分类，是随手写。

现在只留六个，src/config/tags.json 是唯一来源，src/content.config.ts 的 superRefine 会拦下白名单外的任何值，报错直接告诉你可用集合：

标签放什么现有

3.5 全文搜索：三档实测，能不能不涨

你的约束是「不希望项目随文章增多而占的空间更大（更大太多）」。这个约束可以量化，所以我没有停留在估算，而是拿当前 dist 真跑了一遍 Pagefind（3 分钟，三种索引范围）。

方案索引体积每篇100 篇时能力
现状：DOM 过滤标题 / 描述 / 标签000只能按标题找，正文里的词搜不到
Pagefind：只索引正文 .prose247 KB≈16 KB≈1.6 MB真全文，带高亮与片段
Pagefind：索引整页（含导航、目录、页脚）412 KB≈16 KB≈4 MB同上，但每页都把导航和目录重复索引一遍，噪声大
Pagefind：只索引小标题8.6 KB≈0.7 KB≈70 KB近似「目录搜索」，不是全文

实测条件：dist 现状（15 个内容页 / 6,325 词 / 正文约 213 KB UTF-8），Pagefind 1.x，zh-cn。index + fragment 两个目录合计为「索引体积」，不含 pagefind.js（45 KB）与 wasm（68 KB）——那部分是固定成本，只加载一次。

三个关键结论：

  1. 索引不进仓库。dist/ 在 .gitignore 里，Pagefind 的产物跟着构建走。所以「项目变重」这件事不会发生在 git 上，只会发生在发布产物与访客的一次性下载上。这一条直接解掉了你担心的那一半。
  2. 增长是线性的，约 16 KB/篇。15 页 247 KB，100 篇约 1.6 MB。作为参照：public/images 现在就有 9 MB 源图。真正让仓库变大的是图，不是索引。
  3. 「收窄索引范围」比「换工具」有效。整页 412 KB → 只索引正文 247 KB（−40%），再收到只剩小标题 8.6 KB（−98%），但那就不是全文搜索了。中间没有第三个档位：Pagefind 不支持「每段只索引第一句」这种裁剪。

建议：上 Pagefind，索引范围限定 .prose，并加一条预算闸门。

# package.json
"search": "pagefind --site dist --output-subdir pagefind"
# 构建后：index + fragment 超过 2 MB 就让 CI 红，逼着回头看要不要降档

降档预案（闸门红了才用）：把 data-pagefind-body 从 .prose 挪到「只包住 h2/h3」的容器上，体积掉到 70 KB 量级，代价是只能搜小标题。

两条已知短板，先说清楚：① Pagefind 对 zh-cn 不做词干化（构建日志会明说），所以搜「翻译」不会自动命中「翻译者」，只能靠前缀匹配；② 首次搜索要下载 113 KB（js + wasm），在慢网下会有一次可感知的等待。这两条都不致命，但决定了「搜索框不要放在首屏最显眼的位置」——它该是辅助，不是入口。

一条不推荐的路线：「不建索引，搜索时按需 fetch 单页 HTML 做本地匹配」。听起来索引恒为 0，实际每次搜索要拉 8–15 个页面（0.5–1 MB），比 247 KB 的索引大一个量级，而且首字延迟从 0 变成 1–3 秒。省的是磁盘，赔的是体验，不划算。

3.6 术语集与用语习惯：怎么随篇数积累

译到第 20 篇时，拖慢速度的不是生词，是「上次那个词我怎么译的来着」。所以这次不是写一份文档，是搭一个能自己发现漂移的三件套：

件管什么怎么用
data/glossary.json词：日文原词 → 统一译法 + 明确不该出现的写法译前当词表扫，译后补 3–5 条
scripts/check_glossary.py一致性：统计每个词的出现次数，把「异形」列出来npm run check:glossary；--strict 可接 CI
README/translation-style.md句子：标点、人称、敬语、台词、数字、中英混排很少改；改之前先想清楚

首次跑的结果就是它的价值证明——25 条术语、8 篇文章、81,597 字，抓出 4 条异形：1 条是真不一致，3 条是规则定得太严。后三条同样有价值，它们说明词表本身需要收，而不是正文需要改。

异形出现处理
剧本家（应为「编剧」）2改正文。同一篇里既写「编剧」又写「剧本家」，读者会觉得是两个人译的
上市 / 开发方 / 设置1 / 2 / 2判定为规则太严，从词表里删掉——「线上市场」里的「上市」是误报，「让开发方细调」比「开发商」更自然，「图层设置」本来就该用「设置」

为什么只做检查、不做自动抽取：试过分词 + 频次提候选，结果是满屏「作品」「游戏」「先生」。术语的价值在「有争议」，而争议只有人知道。机器负责「你说过的和现在写的不一样」，人负责「哪个才对」。这条分工也写进了文档，避免以后有人想「优化」成自动抽取。

规模控制：词表的目标是 60–80 条，不是 500 条。判断标准一句话——这个词如果下次译错，读者会觉得「前后不是一个人」吗？ 会，就补；不会，别补。膨胀的词表没人看，等于没建。

4.3 Frost 那个站，有什么值得抄

先给结论：它的视觉不能抄，它的信息结构可以抄一半，而且其中一半现在不该抄。

frost.cn.xueayi.site 是一个「每日观察站」：左侧固定导航（工作空间 / 每日阅读 / 个人管理），右侧是分栏的日报（AI、科技前沿、人文社科、金融理财、健康与安全），外加一个「运行概览」和一个「订阅与额度」。配色是深藏青侧栏 + 米白纸面 + 薄荷绿强调色，圆角 6–12px，14px 正文。

它的做法值不值得抄理由
来源可回溯：每条结论都能点回原文（代码里有 cited / provenance / source_coverage 三层结构） 值得 本站日报的 sources 现在是完全隐藏的（只用来内部回溯，页面不显示）。这是最该抄的一条：把每条「详细」末尾加一个可展开的「出处」，读者能自己验证，AI 整理的信任成本立刻降一档
状态卡带日期：运行概览把「数据源 / 服务 / 备份 / 项目」做成卡片，每张都有时间戳，文案是「每个状态都有日期，未知也清晰可见」 值得 本站的对应物是「抓取健康度」：最后一次成功抓取、当期条目数、跳过的账号数。但别放 /daily/——你刚要求那里不要多余文字。放 public/docs/ 的运维页，或 /daily/rss.xml 旁边的状态文件
栏目自带一句话定位（每个分区顶部一句「这栏看什么」） 现在别抄 这正是你刚删掉的东西的另一种形式。等 M5 之后如果觉得列表太素，再考虑放在月份分组标题下而不是每期标题下
卡片化条目 + 分区导航 不抄 它一天是多条短讯的聚合，卡片适合「扫一眼就关掉」；本站一期是一篇两千字上下的长文，卡片会把阅读切成碎片
多栏目并列（AI / 科技 / 人文 / 金融 / 健康） 不抄 它是聚合型产品，本站是单一主题的垂直记录。加栏目等于把「声优动态」稀释掉
配色、圆角、阴影 不抄 与本站黑白灰铁律直接冲突。参考它只会让两套视觉打架

一句话：Frost 的强项是「让人相信这些结论有出处」，本站的强项是「把一天的事写成一篇能读的文章」。该抄的是前者，不是后者。

5.2 逐条过一遍：抄 / 现在别抄 / 不抄

它的做法值不值得抄理由
首屏先说「你会得到什么」：「把零散的知识，连成全栈地图」+ 一句副句 + 一个具体动作，之后才讲内容 值得 本站首页第一屏讲的是「我是谁」（名字、学生物的Galgamer、两行 intro），没有一个字说「这个站在做什么」。加一句承诺不用动布局，只是 profile.json 里的一行字
每张卡一行元信息：编号 + 中文标题 + 英文副名 + 一行「前置：…」，四行高度一致 值得 抄的是卡内结构，不是网格。本站笔记列表现在是「标题 + 日期 + 标签 + 摘要」，缺的是「一眼能判断要不要点」的那行——日期、标签、字数压成一行就够
贯穿式走查：「一个请求，如何变成一个页面？」浏览器 → 网络 → 服务端 → 数据库，四个节点串成一条线，还有一句「← 响应让界面发生变化」收尾 值得 本站有一件现成的对应物：一期日报怎么来的——302 个账号 → x.jsonl → 归类 → 出稿 → 判卷 → 6 个出口。这条链路现在只写在 docs/daily-report-guide.md 里，是给人读的长文，没有一张图
图例：「必须掌握：能解释、能审查 / 理解即可：知道边界和取舍 / 竖线表示推荐顺序，实际依赖见「前置」」 现在别抄 这正是上一轮从 /daily/ 删掉的东西的另一种形式。日报那三个栏目按钮（声优 / 社团 / 厂商）确实没有说明，但你要的是「列表里不要多余文字」——真要做，放 public/docs/ 的运维页，不放列表页
四列阶段网格：一列一个 PHASE，横向读是「推荐顺序」 不抄 它有 18 个主题，每列 4–6 张，网格才立得住。本站笔记现在 8 篇，摊进四列是每列 2 张——那不是地图，是空货架。等 15 篇以上再谈
前置依赖（严格 DAG）：每张卡标「前置：请求旅程 · HTTP」，第一张写「起点 · 无前置要求」 不抄 它的 18 个主题是教学单元，先学 A 才看得懂 B，这是真的。本站笔记是独立文章——访谈译文、工具笔记、术语讨论之间没有依赖关系，硬造一张 DAG 就是伪结构，读者按它去读会踩空
「继续学习」+ 完成勾选：localStorage 记进度，点过的节点变绿 不抄 要客户端状态，直接撞上零 JS 铁律。而且本站没有「学完」这个概念——笔记是读物，不是课程
hash 路由 SPA：#/topic/07 这类地址，整页靠 JS 渲染 不抄 关掉 JS 就是空白页，每张卡没有独立 URL，也就没有独立的 OG 图、没有 RSS 条目、没有被引用的锚点。本站 26 个静态 HTML 的整个价值就在这一点上
绿色系配色 + 8–11px 字号 不抄 颜色与黑白灰铁律直接冲突。字号更要注意：它把英文副名压到 8px 是因为那行只是装饰；中文没有大小写和词间距，11px 的正文读起来是折磨

还有一条不算抄不抄，算提醒：它用 270 KB 的 JS 换来一张能点、能记进度、能筛「必须掌握 / 理解即可 / 用时查阅」的地图。这个交换对教学站是划算的——用户会回来第二十次。本站的读者是「搜到一篇访谈，读完就走」，同一个交换不划算。

5.3 真要动手，落在哪三处

三条都不用写 JS，按成本从低到高：

优先级做什么动哪个文件验收
P1首页第一屏加一句「这个站在做什么」——一句承诺，不是自我介绍src/config/profile.json（tagline 或 intro[0]）375px 宽下第一屏仍能看见头像、名字、承诺三样，且不出现横向滚动
P2笔记列表每行补一行元信息：日期 · 标签 · 字数src/pages/blog/index.astro、components.css不加任何 JS；列表总高度增幅 < 15%；窄屏下这行能折行不溢出
P2一页「一期日报是怎么来的」：302 账号 → 6 个出口的链路图public/docs/daily-pipeline.html（新页）每个箭头都能点回对应文件或命令；npm run links 全绿

不做：四列地图（等 15 篇）、前置依赖、学习进度、hash 路由、绿色系。这五项再讨论一次的成本高于收益——理由在 §5.2，逐条写了。

5.4 一句话

它把「知识」排成一张图，本站把「一天」写成一篇文。图要靠前置关系和进度记忆才立得住，这两样本站都不该有。能抄的只有两件：首屏先说承诺，和卡片里给一行元信息——前者是文案，后者是排版，都不需要一克 JavaScript。
