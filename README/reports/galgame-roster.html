四个栏目里，原画最好办：这一行的画师几乎都有 X，而且粉丝多、发图勤，一天能出十几条可用素材。シナリオ次之，但活跃度差一个量级（多数 0.2–1 条/天），得靠「说了什么」而不是「说了多少」来选。ディレクター最难：galgame 的导演极少有个人号，能查到的只有中澤工一个，其余（下條水月、三舛啓、藤原将、酒井伸和）连 Wikipedia 条目都没有——这一栏第一版基本是空的，建议先不做，或者用「ブランド代表／プロデューサー」来凑。情报号反而是短板：专门报 galgame 的号本来就少（Moepedia 已在册、BugBug 編集部、萌えゲーアワード），剩下的都是泛游戏媒体。

一个必须先解决的结构问题：现在的 CI 塞不下这 24 个号。

X-Reader 的 accounts.yaml 现在 302 个号，一轮抓取约 19.6 分钟，update.yml 的超时是 20 分钟——已经贴着上限。再加 24 个（+8%）约多 1.6 分钟，必然超时。所以 Galgame 版不能直接往同一个 accounts.yaml 里加，得走下面三条之一：

  1. 独立 workflow（推荐）：galgame.yml，自己的 accounts.galgame.yaml + 自己的 data/items/galgame.jsonl，和声优那条线完全解耦，超时互不影响；
  2. 同一个 workflow 里拆成两个 job（各自 20 分钟预算），但要确认 Actions 的总时长配额；
  3. 轮流抓：单双日各抓一半，数据攒两天再出一期——代价是「今天发的东西明天才进日报」。

这件事没定下来之前，名单只能先放着看，进不了流水线。

1. 这份名单是怎么核的

没有用「我记得他的号是 xxx」这种来源——猜出来的 handle 一旦错，日报里就是别人的内容，比漏一个人严重得多。流程是两步：

  1. 拿官方出处：查 ja.wikipedia 对应条目的「外部リンク」（MediaWiki prop=extlinks 接口），取指向 x.com / twitter.com 且不是 /status/ 的那条——那是编者维护的官方账号链接，不是搜索结果里的二手信息。
  2. 逐个复核：用 fxtwitter 的公开接口取账号资料与最近 20 条，核对三件事——显示名对不对、粉丝数量级合不合理、最近有没有在发。粉丝 0–200 且最后一条是 2010 年代的，一律判为同名路人号丢掉。

表里的「节奏」= 最近 20 条覆盖的天数换算出的每日条数，比「最后发帖日期」更能说明这个人是不是真的在活跃（有人一天转 5 条但两个月没原创）。

7. 待你确认的四件事

  1. 栏目怎么切。建议在 daily-roster.json 的 categories 里加一栏 { "id": "galgame", "label": "Galgame" }，role 用 scenario / illustrator / director / info。这样日报页的筛选按钮会自动多出一个「Galgame」，和现有的声优／制造商互不干扰。
  2. CI 怎么拆（见第 0 节的三条路）。这个不定，名单加进去也抓不动。
  3. ディレクター这一栏做不做。只有 1 个人，单独一栏意义不大；建议并进シナリオ，或者用「ブランド代表」替代。
  4. 泛游戏媒体挂不挂。我倾向只挂 AUTOMATON 一个（配 max_items: 3），4Gamer／ファミ通先不挂——它们的 galgame 占比太低，会让模型在几百条里挑。
