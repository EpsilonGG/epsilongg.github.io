能直接搬到你站上的六个点子

按「改动量 ÷ 新鲜度」排的，不是按 star。

  1. 给日报加「配图候选」环节。来自 WeeklyImageToolbox
    现在日报只有文字和链接。可以照它的三段式：抓候选（作品官网 / VNDB / Steam）→ 人工逐条核来源 → 导出确认结果。你已经有 npm run images 和 manifest，缺的只是「候选池 + 审图」这一层。审图界面可以做成 /admin/images 的本地页，不进 dist。
  2. 把固定 30 分钟抓取换成自适应轮询。来自 kun-domain-monitor
    它的规则很干净：离事件远就一周一次，近了 15 分钟，临门一分钟。你的 X-Reader 现在是固定间隔，发售日/生诞祭那几天其实可以临时升频。顺带抄它「阶段跃迁才通知」——只在「预约开始」「开始发售」这种状态变化时出稿，而不是每天全量重写。
  3. 做站内「口味测试」。来自 gal-criticism-toolkit-view
    问卷 + 小游戏 → 口味画像 → 推荐作品。纯前端就能跑，和你「无后端」的约束完全兼容。数据可以直接从你已有的 data/ 里出，不用引第三方 API。做完是个很好的入口页，比链接库更容易被转发。
  4. 加一条「频道归档」出口。来自 kun-channel-to-site
    你已经有 /daily 的六个出口，但都是「一期一页」。频道归档是另一种切法：按时间线连续读，不按天切。Telegram/QQ 频道 → 静态页这套结构可以直接套在现有的 data/daily/ 上，只是换一种聚合。
  5. 视频 → 可点的东西。来自 movie2galagame
    把 PV 抽帧、切片、字幕转成 Ren'Py 项目，本质是「线性素材 → 可交互」。轻一点的版本：日报里每期挑一条 PV，自动抽 6 帧做成分镜图，比一张封面图信息量大得多。
  6. 把「履历」做成一个页面。来自 GalStar
    VNDB API 代理 + 个人收藏 + 评分。你的站现在是「输出型」（日报、笔记），缺一个「我玩过什么」的静态页。数据手写在 src/config/，渲染成时间轴 + 评分分布，不需要后端。

三个可以直接抄的工程习惯

  • 幂等按「业务日 + 群/频道」建主键，重启不重发。你日报的期号已经是这个思路，但 publish 环节还没有「今天发过就不再发」的硬约束。
  • 结果未知就不补发。发送超时记 uncertain 而不是失败，宁可不发也不刷屏。日报的 push_site.py 现在失败就裸重试，值得区分「确定失败」和「不知道成没成」。
  • 数据过期就不发。源数据超过 N 分钟直接 skip 并记原因，比发一条半旧的日报好。这和你的 apply 校验是同一层，可以合并。
