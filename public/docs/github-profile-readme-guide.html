01它到底是什么

GitHub 有一个隐藏规则：如果存在一个和你的用户名完全同名的仓库，且仓库根目录有 README.md， 那么这份 README 会渲染在你的个人主页最上方。

对你的账号来说，就是仓库 github.com/EpsilonGG/EpsilonGG 里的 README.md。 它不是普通仓库，不参与项目列表的展示逻辑，作用相当于一张可以随便排版的个人名片。

要点说明
仓库名必须与用户名完全一致（大小写不敏感），EpsilonGG
可见性必须 Public，Private 不会显示
入口文件根目录 README.md，文件名固定
渲染标准 GitHub Markdown，支持 HTML、表格、图片、徽章
不支持的<style>、<script>、外链 CSS、iframe 都会被过滤

一句话：主页 README = 一个叫 EpsilonGG 的公开仓库里的 README.md。 改它，就是改主页。

02从零建起来（5 步）

  1. 新建仓库。 打开 github.com/new，Repository name 填 EpsilonGG。 如果名字打对了，页面上会出现一句绿色提示： “You found a secret! EpsilonGG/EpsilonGG is a special repository…” —— 看到这句话说明你走对了。
  2. 勾选 “Add a README file”。 可见性选 Public。其余选项（模板、gitignore、license）全部留空。
  3. 点 Create repository。 创建完成后，回到 github.com/EpsilonGG，主页顶部就会显示这份 README。 默认内容是一行 # EpsilonGG。
  4. 克隆到本地（推荐）。 因为要和网站仓库配合，建议放在网站仓库旁边： 
    cd ~/Desktop
git clone https://github.com/EpsilonGG/EpsilonGG.git profile
    这样目录结构是 github page work/ 与 profile/ 平级， 同步脚本的相对路径正好对得上。
  5. 先写一版能看的。 用第 5 节的骨架模板替换掉默认内容，提交： 
    cd profile
git add README.md
git commit -m "docs: initial profile readme"
git push

常见误会：改网站仓库的 README.md 不会影响主页。 那是项目说明，主页读的是 EpsilonGG/EpsilonGG 这个仓库里的那份。

03三种内容来源，选一种

主页 README 的内容通常来自三个地方，混着用也可以，但要清楚各自的代价。

A · 纯手写

全部内容自己敲。完全可控，但网站更新了要手动同步一遍，容易忘。

B · 脚本同步（本项目）

用 marker 划出三块区域，脚本从网站配置和文章里取值填进去。手写部分不受影响。

C · 第三方卡片

贴统计卡片、徽章的图片链接。省事好看，但依赖别人的服务，挂了就是裂图。

推荐组合：B 管动态内容（简介 / 导航 / 最新文章），A 管静态排版（标题、项目介绍）， C 少量点缀。这也是本站已经实现的方案。

## 手写区域

这一段脚本永远不会碰。

本地运行

# 在网站仓库根目录执行
python scripts/sync_profile_readme.py --readme ../profile/README.md

# 只想看要不要更新，绝不写文件
python scripts/sync_profile_readme.py --readme ../profile/README.md --check

# 最近文章只想放 3 条
python scripts/sync_profile_readme.py --readme ../profile/README.md --max-posts 3

退出码

码含义该怎么办
0成功；--check 时表示已经同步无
1--check 检测到需要更新去掉 --check 再跑一次
2README 结构错误：marker 缺失、重复、顺序错、嵌套按上表检查三对 marker
3输入错误：文件不存在、JSON 读不了、参数不对检查路径和配置文件

交给 GitHub Actions

网站仓库里已经带了 .github/workflows/sync-profile-readme.yml，但它是手动触发的， 而且需要一个有权限的 token，否则会直接跳过，不影响网站部署。

  1. 生成 token：GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens。Repository access 只选 EpsilonGG/EpsilonGG， 权限给 Contents: Read and write。有效期按自己习惯选。
  2. 把它存进网站仓库（epsilongg.github.io）的 Secret， 名字必须是 PROFILE_README_TOKEN。
  3. 打开网站仓库的 Actions → Sync profile README → Run workflow， 填 readme_repo 为 EpsilonGG/EpsilonGG， dry_run 先保持 true 试跑一次（只检查，不写入）。
  4. 确认 dry run 通过后，再跑一次并把 dry_run 设为 false， workflow 会自己 commit + push 到个人资料仓库。

为什么不自动跑？主页 README 更新频率低，手动触发可以避免每次写文章都产生一条跨仓库提交。 如果你希望每次发布文章后自动同步，把 workflow 的 on: 改成 push + paths 过滤 src/content/blog/** 即可。

很多教程会让你用 github-readme-stats 的博客文章卡片，或者 RSS 转图片的服务。 既然本站已经有 rss.xml 和同步脚本，直接用 POSTS 区块更可靠—— 纯文本链接，永远不会裂图，还能被搜索引擎读到。

07维护节奏

什么时候做什么花多久
发了新文章 跑一次同步脚本，提交个人资料仓库 1 分钟
改了 profile.json 的 intro / tagline 同上，PROFILE 区块会自动跟着变 1 分钟
加了新的站内页面 改 navigation.json，再同步 2 分钟
换了头像 主页头像 GitHub 会自动换；网站那份要手动重新下载 2 分钟
每季度 扫一遍外链和第三方卡片，删掉失效的；看看「在做的事」还准不准 10 分钟

判断标准很简单：主页上任何一条信息，如果三个月后回来看是错的，就不该写死在里面。 能由脚本生成的交给脚本，剩下的控制在一屏之内。

08八个常见坑

1. 仓库名打错

写成 epsilongg 以外的任何名字（比如 profile、EpsilonGG.github.io）都不会显示。 必须是和用户名一模一样。大小写不敏感，但建议照抄。

2. 仓库是 Private

Private 仓库的 README 不会出现在主页，且不会有任何报错提示，很容易以为是自己写错了。

3. marker 写坏

脚本对结构是零容忍的：少一个、多一个、顺序反了、嵌套了，都会直接以退出码 2 失败，不会猜你想干什么。 改动 README 结构后，先跑 --check 确认。

正确的顺序：

<!-- PROFILE:START --> … <!-- PROFILE:END -->
<!-- NAV:START -->     … <!-- NAV:END -->
<!-- POSTS:START -->   … <!-- POSTS:END -->

4. 把 <style> 写进 README

GitHub 的 Markdown 渲染器会把 <style>、<script>、class 属性全部过滤掉。 想要样式只能用行内 style="…"（支持得很有限），或者干脆用图片和 align 属性。

5. token 权限给太大

同步只需要一个仓库的 Contents: Read and write。 不要用 classic token 勾 repo 全权限——一旦泄露，影响的是整个账号。

6. 相对路径图片

主页 README 里的 ![](./img/a.png) 只有在你把图片一起提交到个人资料仓库时才有效。 引用网站上的图要用绝对地址，例如 https://epsilongg.github.io/images/avatar.jpg。

7. 改完没生效就以为失败了

主页有缓存，通常几十秒到几分钟。强制刷新（Ctrl + F5）再看。 如果是 Actions 推的，先去 Actions 页面确认那一次真的跑成功了。

8. 内容越堆越多

统计卡片、奖杯、访客计数、技能进度条、动态横幅……堆满一屏看着热闹，实际没人往下翻。 主页的作用是让人三秒内知道你是谁、在做什么、去哪里看更多，其余都该放进网站。

09上线前检查清单

  • 仓库名是 EpsilonGG，Public，根目录有 README.md
  • 三对 marker 都在，顺序是 profile → navigation → posts，没有重复和嵌套
  • python scripts/sync_profile_readme.py --readme ../profile/README.md --check 返回 0
  • 主页上点一遍所有链接，站内链接都能打开（/、/morelinks/、/archive/、文章页）
  • 深色模式下截图看一眼，图片和徽章没有突兀的白底
  • 手机宽度下（约 390px）没有横向滚动条
  • 没有第三方卡片处于裂图状态
  • 版权/转载声明那一行还在

下一步：如果还没建仓库，从第 2 节开始；已经建好了，直接跳到第 4 节把 marker 补上， 跑一次 --check，看到退出码 0 就算接好了。
